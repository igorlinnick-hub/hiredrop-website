Обновлено: 2026-09-21 · ветка: main (всё смержено)

## Состояние

**History стал поверхностью доказательства, а не журналом.** Строка раскрывается в
запись о подаче: ссылка на вакансию, отправленный PDF, письмо, тейлор-резюме — бумажными
чипами `.hd-chip` (globals.css). Hover поднимает на 1px и ловит ореол `var(--accent)`:
днём золотой, ночью фиолетовый, обе темы из одного рецепта. Чернила намеренно не тронуты —
по скину 09-19 чёрное зарезервировано за главным действием экрана, чипы вторичны.
`Copy → Copied` живёт на самой кнопке, без тостов.

**Статус заявки теперь ставит человек.** Строка не могла уехать из `applied` вообще:
единственным писателем был почтовый цикл, а он выключен по делу — читал ОДИН общий ящик
и матчил по названию компании ЧЕРЕЗ ВСЕХ юзеров. Честная замена — сам юзер: письмо
работодателя он и так видит у себя в почте.

- Чип статуса = кнопка с меню на 4 пункта, у каждого подсказка человеческим языком
  («They want to talk»). Тот же список, что `USER_SETTABLE_STATUSES` на бэкенде, и по той
  же причине без `applied_unconfirmed`: это сигнал честности исполнителя, а не значение
  для ручной записи.
- **Цвет несёт смысл**: зелёный = ответили и хорошо, красный = ответили и нет,
  нейтральный = тишина. Именно это делает «Interview» читаемым рядом с «Applied».
- Запись оптимистичная **с откатом** и строкой ошибки: статус, который молча не
  сохранился, хуже отсутствующего.
- Метрики и группировка читают изменённый статус, поэтому Responses, response rate и
  кнопка «Prep for this» двигаются в тот же момент.

## Последний заход

- Пикер живёт внутри строки, которая сама `role="button"` — все обработчики глушат
  всплытие, иначе выбор статуса заодно раскрывал бы запись. Закрывается по клику наружу
  и по Escape. Проверено в браузере: меню открылось, строка НЕ раскрылась.
- `onSetStatus` — проп для `/preview/history-chips`: превью публичное, сессии нет, запись
  подменяется заглушкой, чтобы пикер оставался кликабельным.
- Проверено на живом проде в залогиненном окне: 45 строк, 45 пикеров, 93 чипа.
